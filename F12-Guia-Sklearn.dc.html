1. Una API para todos los modelos

En scikit-learn todo lo que aprende de los datos es un estimador: un objeto que se crea con sus hiperparámetros y se ajusta con fit. Lo que se aprende queda guardado en atributos que terminan en guion bajo (coef_, mean_, classes_). Un KNN, una regresión logística y un StandardScaler se usan de la misma forma; cambia solo qué métodos ofrecen después de ajustarse.

2. Pipelines: el preprocesamiento dentro del modelo

En el artículo de preprocesamiento vimos la regla contra el data leakage: ajustar todo solo con train. Hacerlo a mano paso por paso es frágil. Un Pipeline encadena transformadores y un modelo final en un solo estimador; un ColumnTransformer aplica pasos distintos a columnas distintas. Al llamar fit, cada paso se ajusta con los datos que recibe, en orden.

Para pipelines cortos, make_pipeline(StandardScaler(), KNeighborsClassifier()) hace lo mismo y nombra los pasos automáticamente. Los nombres importan después: para referirnos al hiperparámetro C del paso "clf" escribimos clf__C, con doble guion bajo.

3. Validación cruzada y búsqueda de hiperparámetros

Una sola partición train/validación da una estimación ruidosa. Con validación cruzada en k bloques, entrenamos k veces, cada vez validando en un bloque distinto, y promediamos. Como el pipeline es un estimador, el preprocesamiento se vuelve a ajustar en cada vuelta solo con los bloques de entrenamiento.

{{ f.score }}

{{ foldDesc }}

GridSearchCV repite esa validación cruzada para cada combinación de hiperparámetros, se queda con la mejor y reentrena con todo X_train:

from sklearn.model_selection import GridSearchCV

grid = GridSearchCV(modelo, {"clf__C": [0.01, 0.1, 1, 10]}, cv=5)
grid.fit(X_train, y_train)
grid.best_params_          # {'clf__C': 1}
grid.score(X_test, y_test) # una sola vez, al final

Para clasificación, cv=5 ya usa StratifiedKFold, que conserva la proporción de clases en cada bloque. En series de tiempo usamos TimeSeriesSplit, porque mezclar el futuro en el entrenamiento también es leakage.

Sin etiquetas no hay nada contra qué validar, así que los modelos de la Fase 3 se eligen con otras herramientas: silhouette_score para el número de clusters, bic para mezclas gaussianas, la varianza explicada para PCA y la gráfica de k-distancias para DBSCAN. Si existen etiquetas que no usamos para ajustar, adjusted_rand_score mide qué tanto las recuperó el clustering. La excepción es PCA como paso previo a un modelo supervisado: ahí n_components es un hiperparámetro más y va en GridSearchCV.

5. Errores frecuentes

  • Ajustar un transformador con todos los datos antes de separar. La solución es meterlo en el pipeline.
  • Olvidar escalar en modelos que usan distancias o gradiente: KNN, SVM, regresión regularizada, MLP. El síntoma típico es un ConvergenceWarning o un KNN que solo mira una variable.
  • Evaluar en test varias veces mientras ajustamos hiperparámetros. El test deja de ser una muestra nueva; para elegir usamos validación cruzada.
  • Reportar solo accuracy con clases desbalanceadas. classification_report muestra precisión, recall y F1 por clase.
  • Comparar labels_ con y usando accuracy. Los números de cluster son arbitrarios; usamos adjusted_rand_score o una tabla cruzada.
  • Usar t-SNE como preprocesamiento. No tiene transform y cambia con cada corrida. Para reducir dimensiones antes de un modelo usamos PCA.
  • Pasar un vector como X. Con una sola variable, X sigue siendo una matriz: df[["edad"]], no df["edad"].
