Teoría: Fase 2 · El Perceptrón · scikit-learn 1.9.1

1. El dataset

load_breast_cancer tiene 569 tumores con 30 variables numéricas calculadas sobre imágenes de núcleos celulares: radio, textura, área, suavidad y otras, cada una como media, error estándar y peor valor. El objetivo vale 0 para maligno (212 casos) y 1 para benigno (357).

from sklearn.datasets import load_breast_cancer

datos = load_breast_cancer(as_frame=True)
X, y = datos.data, datos.target
X.shape            # (569, 30)
y.value_counts()   # 1: 357, 0: 212
datos.target_names # ['malignant', 'benign']

2. Código paso a paso

Primero separamos un 20 % para test, estratificado porque las clases no están balanceadas.

from sklearn.model_selection import train_test_split

X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.2, stratify=y, random_state=42)

Después ajustamos. Perceptron recorre train una vez por época y corrige los pesos con cada error. Se detiene al llegar a max_iter épocas o cuando la pérdida deja de bajar más de tol durante n_iter_no_change=5 épocas seguidas.

from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import Perceptron

clf = make_pipeline(StandardScaler(),
                    Perceptron(max_iter=1000, tol=1e-3, random_state=0))
clf.fit(X_train, y_train)
clf[-1].n_iter_    # épocas que corrió

Finalmente, medimos en test con el reporte por clase. En este problema importa más no dejar pasar un maligno, así que miramos el recall de la clase 0.

from sklearn.metrics import classification_report

clf.score(X_test, y_test)
print(classification_report(y_test, clf.predict(X_test),
                            target_names=datos.target_names))

3. Escalar cambia lo que aprende

La regla de actualización suma el vector x completo a los pesos en cada error: w ← w + y·x, b ← b + y. Si una variable se mide en cientos y otra en decenas, la primera domina cada corrección. Con dos variables, textura media y área media, se ve en el plano.

En los dos casos los errores por época no llegan a cero. Las clases se traslapan, los datos no son linealmente separables y la regla nunca deja de corregir. Por eso scikit-learn se detiene por tol y no porque haya encontrado una frontera perfecta.

4. Cómo interpretar la salida

El perceptrón no da probabilidades: no tiene predict_proba. Lo que sí tiene es decision_function, que devuelve w·x + b. El signo decide la clase y la magnitud crece con la distancia a la frontera. Como entrenamos con StandardScaler, cada peso de coef_ es el efecto de subir una desviación estándar en esa variable.

import pandas as pd

clf.decision_function(X_test.iloc[:3])  # positivo → benigno (1)

pesos = pd.Series(clf[-1].coef_[0], index=X.columns)
pesos.sort_values().head()   # las que más empujan hacia maligno

Hay que leer esos pesos con cuidado. Muchas de las 30 variables están muy correlacionadas (radio, perímetro y área miden casi lo mismo), y el perceptrón puede repartir el efecto entre ellas de cualquier forma. Si necesitamos probabilidades, LogisticRegression tiene el mismo tipo de frontera lineal y sí las da; la veremos en la Fase 5.

5. Errores frecuentes

  • No escalar. El área domina cada actualización y el intercepto tarda cientos de correcciones en alcanzarla. La figura 1 lo muestra.
  • Pedir probabilidades. clf.predict_proba lanza AttributeError. Usamos decision_function o cambiamos de modelo.
  • Leer un ConvergenceWarning como un error del código. Con datos no separables el perceptrón nunca converge del todo; el aviso dice que llegó a max_iter.
  • Olvidar que 0 es maligno. En recall_score la clase positiva por defecto es 1; para medir malignos pasamos pos_label=0.
  • Confiar en una sola corrida. El resultado depende del orden de las muestras. Comparamos varios random_state o usamos validación cruzada.
